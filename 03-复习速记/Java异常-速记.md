# Java 异常 - 复习速记

## 1. `throw` 和 `throws` 的区别

- `throw`：用在方法体内部，主动抛出一个具体的异常对象
- `throws`：用在方法声明上，声明当前方法可能抛出的异常类型，当前方法不处理，交给调用方处理

## 2. 编译时异常和运行时异常的区别

- 编译时异常：编译阶段会检查，必须通过 `try-catch` 或 `throws` 处理
- 运行时异常：编译阶段不会强制处理，通常是代码逻辑问题导致的

## 3. 为什么业务异常通常继承 `RuntimeException`

- 业务异常通常是可预期的业务错误
- 不需要调用方层层 `try-catch` 或 `throws`
- 代码更简洁，也方便统一异常处理

## 4. `finally` 一定会执行吗

- 通常会执行
- 但在 JVM 直接退出、程序崩溃、机器断电等情况下，可能不会执行
- 如果 `finally` 内部再抛异常，说明它已经执行了，只是执行过程中出错

## 5. `final`、`finally`、`finalize` 的区别

- `final`：关键字，可修饰类、方法、变量
- `finally`：异常处理中的代码块，通常用于收尾和释放资源
- `finalize`：`Object` 类中的方法，和垃圾回收相关，现在不推荐使用

## 6. 什么时候用 `try-catch`，什么时候用 `throws`

- 当前方法知道怎么处理异常，用 `try-catch`
- 当前方法不适合处理异常，用 `throws` 向上抛出
- 在分层里，底层方法通常更适合先抛出，由更上层决定如何处理
