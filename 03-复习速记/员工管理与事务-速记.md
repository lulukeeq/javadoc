## 2. 分页查询

- 前端传：`page`、`pageSize`
- 后端回：`rows`、`total`
- 起始索引：

```text
(page - 1) * pageSize
```

- 原始方式：手动 `count + limit`
- PageHelper：`startPage(page, pageSize)` 后执行查询

## 3. PageHelper 关键点

- `PageHelper.startPage(...)` 必须写在查询前面
- 只对后面紧跟的第一条查询生效
- `@Select` SQL 末尾不要加分号
- 返回结果虽然先用 `List<Emp>` 接，但底层可以强转成 `Page<Emp>`

## 4. 条件分页查询

- 日期参数用：

```java
@DateTimeFormat(pattern = "yyyy-MM-dd")
```

- 模糊查询不能写：

```xml
like '%#{name}%'
```

- 正确写法：

```xml
like concat('%', #{name}, '%')
```

- `<if>`：控制单个条件要不要参与查询
- `<where>`：自动生成 `where`，并去掉多余的 `and`

## 5. 新增员工

- `emp`：员工主表
- `emp_expr`：工作经历表
- `image`：通常先传 OSS 地址，再保存到主表字段
- `Emp` 中新增：

```java
private List<EmpExpr> exprList;
```

- Controller 用：

```java
@RequestBody
```

接 JSON 请求体

## 6. 主键回填与批量插入

- 先插 `emp`
- 再拿员工 `id`
- 再给每条工作经历补 `empId`
- 最后批量插入 `emp_expr`

主键回填：

```java
@Options(useGeneratedKeys = true, keyProperty = "id")
```

批量插入：

```xml
<foreach>
```

- `CollectionUtils.isEmpty(emp.getExprList())`：先判断工作经历列表是否为空

## 7. 事务管理

- 事务：一组操作要么一起成功，要么一起失败
- 新增员工里，`emp` 和 `emp_expr` 必须放在同一个事务里
- 一般把事务加在 `Service` 方法上：

```java
@Transactional
```

- 默认只对运行时异常和 `Error` 回滚
- 需要扩展回滚范围时用：

```java
@Transactional(rollbackFor = Exception.class)
```

## 8. 事务传播行为

- `REQUIRED`：有事务就加入，没有事务就新建
- `REQUIRES_NEW`：无论是否有事务，都新建独立事务

- 日志如果想独立保留，更适合 `REQUIRES_NEW`

## 9. ACID

- 原子性：要么都成功，要么都失败
- 一致性：事务前后数据都要正确一致
- 隔离性：多个事务尽量互不干扰
- 持久性：事务结果一旦确定，就永久生效

## 10. 今晚只看这 5 句

1. `start = (page - 1) * pageSize`
2. `like '%#{name}%'` 不行，要用 `concat('%', #{name}, '%')`
3. `PageHelper` 只管后面紧跟的第一条查询
4. 先插 `emp`，拿到 `id`，再插 `emp_expr`
5. `@Transactional` 管的是整个业务方法，不是某一条 SQL

## 11. 文件上传

- 后端接文件核心类型：`MultipartFile`
- 本地保存核心方法：

```java
file.transferTo(...)
```

- 原始文件名：

```java
file.getOriginalFilename()
```

- 为避免同名覆盖：`UUID + 后缀`
- Spring Boot 上传大小可通过：

```yaml
spring.servlet.multipart.max-file-size
spring.servlet.multipart.max-request-size
```

- OSS 主线：
  - 开通 OSS
  - 创建 Bucket
  - 获取并配置 AccessKey
  - 参考官方 SDK 跑通 Demo
  - 集成到上传接口

- 上传接口最终返回的是图片 URL，不是文件本身

## 12. 今晚再多记 3 句

1. 本地上传：`MultipartFile -> 原始文件名 -> UUID新文件名 -> transferTo()`
2. OSS 上传：后端把文件传到 OSS，再把图片 URL 返回给前端
3. 新增员工最终保存的是 `image` URL，不是本地图片文件

## 13. 删除员工

- 删除员工本质上是“组合删除”
- 更稳妥的顺序通常是：先删 `emp_expr`，再删 `emp`
- `Controller` 常用 `List<Integer>` 或 `Integer[]` 接收批量删除 id
- `Mapper XML` 批量删除常用：

```xml
<foreach>
```

- `Service` 层要用事务把两次删除包成一个整体

一句话：

> 删除员工不是删一条记录，而是把主表和工作经历表一起删干净，并保证中途失败能整体回滚。

## 14. 修改员工

- 查询回显常见做法：`emp` 和 `emp_expr` 左连接
- 简单映射用 `resultType`
- 一对多、字段别名较多、需要封装列表时更适合 `resultMap`
- 修改员工常见流程：

```text
更新 emp 主表
-> 删除旧的 emp_expr
-> 重新插入新的 emp_expr
```

- 动态更新常配合：

```xml
<set> + <if>
```

一句话：

> 修改员工的核心不是只改一张表，而是把“主表更新 + 子表重建”作为同一个业务方法处理。

## 15. 全局异常处理

- 统一异常处理器常用：

```java
@RestControllerAdvice
```

- 具体异常处理方法常用：

```java
@ExceptionHandler
```

- 通用异常兜底可以避免每个接口都写重复 `try-catch`
- `DuplicateKeyException` 适合单独处理，返回更友好的提示

一句话：

> 全局异常处理的目标不是“消灭异常”，而是把异常统一收口、统一记录、统一返回给前端。

## 16. 员工信息统计

- 统计接口核心不是查明细，而是“按维度分组”
- 职位统计常见关键词：
  - `GROUP BY`
  - `CASE`
  - 返回 `jobList + dataList` 或 `JobOption`
- 性别统计常见关键词：
  - `GROUP BY`
  - `IF`
  - 返回 `[{name, value}, ...]`
- 统计接口要按前端图表组件最容易消费的结构返回

一句话：

> 统计类接口的重点是“SQL 分组统计 + 按图表需要封装返回结构”，不是只把数据库原始结果直接丢给前端。

## 17. 今晚最后再记 5 句

1. 删除员工时，事务管的是“删主表 + 删子表”这一整组操作
2. 修改员工常见套路是“改主表、删旧经历、插新经历”
3. `resultType` 偏简单映射，`resultMap` 更适合复杂映射和一对多封装
4. `@RestControllerAdvice + @ExceptionHandler` 用来统一异常出口
5. 职位统计更像“两个列表”，性别统计更像 `name + value` 对象数组
