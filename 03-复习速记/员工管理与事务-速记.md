## 2. 分页查询

- 前端传：`page`、`pageSize`
- 后端回：`rows`、`total`
- 起始索引：

```text
(page - 1) * pageSize
```

- 原始方式：手动 `count + limit`
- PageHelper：`startPage(page, pageSize)` 后执行查询

## 3. PageHelper 关键点

- `PageHelper.startPage(...)` 必须写在查询前面
- 只对后面紧跟的第一条查询生效
- `@Select` SQL 末尾不要加分号
- 返回结果虽然先用 `List<Emp>` 接，但底层可以强转成 `Page<Emp>`

## 4. 条件分页查询

- 日期参数用：

```java
@DateTimeFormat(pattern = "yyyy-MM-dd")
```

- 模糊查询不能写：

```xml
like '%#{name}%'
```

- 正确写法：

```xml
like concat('%', #{name}, '%')
```

- `<if>`：控制单个条件要不要参与查询
- `<where>`：自动生成 `where`，并去掉多余的 `and`

## 5. 新增员工

- `emp`：员工主表
- `emp_expr`：工作经历表
- `image`：通常先传 OSS 地址，再保存到主表字段
- `Emp` 中新增：

```java
private List<EmpExpr> exprList;
```

- Controller 用：

```java
@RequestBody
```

接 JSON 请求体

## 6. 主键回填与批量插入

- 先插 `emp`
- 再拿员工 `id`
- 再给每条工作经历补 `empId`
- 最后批量插入 `emp_expr`

主键回填：

```java
@Options(useGeneratedKeys = true, keyProperty = "id")
```

批量插入：

```xml
<foreach>
```

- `CollectionUtils.isEmpty(emp.getExprList())`：先判断工作经历列表是否为空

## 7. 事务管理

- 事务：一组操作要么一起成功，要么一起失败
- 新增员工里，`emp` 和 `emp_expr` 必须放在同一个事务里
- 一般把事务加在 `Service` 方法上：

```java
@Transactional
```

- 默认只对运行时异常和 `Error` 回滚
- 需要扩展回滚范围时用：

```java
@Transactional(rollbackFor = Exception.class)
```

## 8. 事务传播行为

- `REQUIRED`：有事务就加入，没有事务就新建
- `REQUIRES_NEW`：无论是否有事务，都新建独立事务

## 9. ACID

- 原子性：要么都成功，要么都失败
- 一致性：事务前后数据都要正确一致
- 隔离性：多个事务尽量互不干扰
- 持久性：事务结果一旦确定，就永久生效

## 10. 今晚只看这 5 句

1. `start = (page - 1) * pageSize`
2. `like '%#{name}%'` 不行，要用 `concat('%', #{name}, '%')`
3. `PageHelper` 只管后面紧跟的第一条查询
4. 先插 `emp`，拿到 `id`，再插 `emp_expr`
5. `@Transactional` 管的是整个业务方法，不是某一条 SQL

## 11. 文件上传

- 后端接文件核心类型：`MultipartFile`
- 本地保存核心方法：

```java
file.transferTo(...)
```

- 原始文件名：

```java
file.getOriginalFilename()
```

- 为避免同名覆盖：`UUID + 后缀`
- Spring Boot 上传大小可通过：

```yaml
spring.servlet.multipart.max-file-size
spring.servlet.multipart.max-request-size
```

- OSS 主线：
  - 开通 OSS
  - 创建 Bucket
  - 获取并配置 AccessKey
  - 参考官方 SDK 跑通 Demo
  - 集成到上传接口

- 上传接口最终返回的是图片 URL，不是文件本身

## 12. 今晚再多记 3 句

1. 本地上传：`MultipartFile -> 原始文件名 -> UUID新文件名 -> transferTo()`
2. OSS 上传：后端把文件传到 OSS，再把图片 URL 返回给前端
3. 新增员工最终保存的是 `image` URL，不是本地图片文件
