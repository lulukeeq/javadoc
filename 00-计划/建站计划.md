# 建站计划

## 一、目标

当前的 `javadoc/` 继续作为主文档库，只负责：

- Markdown 文档的新增
- Markdown 文档的修改
- Markdown 文档的删除
- 目录结构和主题内容维护

另外新建一个单独的网站工程，用来：

- 读取当前文档库中的 Markdown 内容
- 生成在线文档网站
- 提供目录导航、搜索、主题浏览和在线阅读能力

原则：

> 文档库负责内容，网站工程负责展示，两者分离。

---

## 二、仓库职责划分

### 1. 当前文档库的职责

- 维护学习资料目录结构
- 维护学习笔记
- 维护复习速记
- 维护练习代码说明
- 维护常用片段
- 作为唯一内容源

### 2. 网站工程的职责

- 拉取或读取文档库内容
- 解析 Markdown
- 生成网页
- 构建左侧导航、目录索引、面包屑、搜索
- 提供适合学习和复习的阅读体验

---

## 三、推荐方案

推荐采用：

> 保留 Markdown 文档库作为内容源，新建一个独立工程动态读取或同步读取该文档库，再生成网站。

不建议：

- 直接把当前文档库改造成前端工程
- 在当前文档库里混入大量网站配置
- 把网站样式、构建脚本和学习笔记放在同一个仓库里

---

## 四、网站工程需要实现的能力

### 1. 基础能力

- 支持渲染 Markdown
- 支持展示代码块
- 支持目录导航
- 支持页面内部标题锚点跳转
- 支持全文搜索
- 支持中文路径或中文标题显示

### 2. 结构映射能力

网站工程需要能识别当前文档结构：

- `00-计划/`
- `01-原始资料/`
- `02-学习笔记/`
- `03-复习速记/`
- `04-练习代码/`
- `05-常用片段/`

并在网页上提供对应栏目导航。

### 3. 阅读体验能力

- 首页可展示总导航
- 每个目录可展示自己的 README 导航
- 支持上一篇 / 下一篇跳转
- 支持移动端和桌面端阅读

---

## 五、建议实施步骤

### 第 1 步：新建网站工程

回家后新建单独目录，例如：

```text
study-notes-site/
```

这个目录只放网站工程代码，不放学习主笔记。

### 第 2 步：确定文档来源方式

可选方式：

1. 网站工程直接读取文档库目录
2. 网站工程通过 Git 拉取文档库
3. 网站工程把文档库作为子模块或内容源接入

当前更推荐：

> 网站工程直接读取或同步拉取文档库，不反向修改文档库。

### 第 3 步：先跑通最小版本

第一版先实现：

- 读取 `README.md`
- 展示左侧目录
- 打开具体 Markdown 页面
- 正确渲染代码块

不要一开始就追求复杂主题和花哨效果。

### 第 4 步：补搜索和导航

基础阅读跑通后，再补：

- 全文搜索
- 分类页
- 面包屑
- 上下篇导航

### 第 5 步：再优化样式

最后再考虑：

- 字体
- 配色
- 夜间模式
- 首页布局

---

## 六、当前文档库需要继续保持的约定

为了让网站工程更容易生成页面，当前文档库后续要继续保持：

1. 目录层级稳定
2. 每层尽量有 `README.md`
3. 主题文档命名清晰
4. 同一主题尽量只有一个正式笔记入口
5. 复习速记和正式笔记分开

---

## 七、回家后优先级

回家后建议按这个顺序做：

1. 新建网站工程目录
2. 确定读取当前文档库的方式
3. 跑通 Markdown 渲染
4. 跑通目录导航
5. 再补搜索
